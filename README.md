# Key-Value gRPC Service (Tarantool & Java)

Данный проект представляет собой высокопроизводительный gRPC сервис на Java, использующий **Tarantool 3.2.x** в качестве основного хранилища. Сервис реализует стандартные CRUD операции и потоковую передачу данных (Streaming) для работы с большими объемами информации.

## 🚀 Основные возможности

*   **Атомарный Put**: Сохранение новых и перезапись существующих ключей.
*   **Поддержка Null**: Корректная обработка `null` значений в поле `value` (согласно ТЗ).
*   **Streaming Range**: Эффективное получение диапазона ключей через gRPC Stream.
*   **Масштабируемость**: Оптимизировано для работы со спейсами объемом **5 000 000+ записей**.
*   **Полная асинхронность**: Весь стек (от gRPC до драйвера Tarantool) работает в неблокирующем режиме на базе `CompletableFuture`.

## 🛠 Технологический стек

*   **gRPC** (Protobuf)

## ⚙️ Технические решения

### 1. Работа с 5 000 000 записей
Для исключения ошибок `OutOfMemoryError` при выборке больших диапазонов реализован **асинхронный рекурсивный стриминг**. Данные запрашиваются из Tarantool пачками (batching) и передаются в выходной поток gRPC по мере поступления.

### 2. Консистентность и уникальность
Используется метод `upsert` (или `replace`) через `TarantoolBoxClient`. Это гарантирует уникальность первичного ключа (`key`) и атомарное обновление значения при повторной записи.

### 3. Индексация
Для спейса `KV` настроен индекс типа `TREE`. Это критически важно для выполнения метода `range` за логарифмическое время $O(\log N)$, что обеспечивает высокую скорость даже на 5 млн записей.

## 🔧 Запуск проекта

### 1. Запуск Tarantool
В корне проекта находится `docker-compose.yml`.
```bash
docker-compose up -d
```
*Автоматически создается спейс `KV` с нужной схемой и пользователем `admin:password`.*

### 2. Сборка и генерация gRPC классов
```bash
mvn clean compile
```

### 3. Запуск приложения
```bash
mvn spring-boot:run
```

## 📝 Определение API (Protobuf)

```protobuf
service KvService {
  rpc Put(PutRequest) returns (Empty);
  rpc Get(GetRequest) returns (GetResponse);
  rpc Delete(DeleteRequest) returns (Empty);
  rpc Range(RangeRequest) returns (stream KeyValueResponse);
  rpc Count(Empty) returns (CountResponse);
}
```
